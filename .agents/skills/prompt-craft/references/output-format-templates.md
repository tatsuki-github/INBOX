# 出力形式別テンプレート集

> プロンプトで LLM の出力形式を制御するためのテンプレート。Step 5 で参照。

---

## JSON 出力テンプレート

### 基本形（スキーマ指定）

```
以下の入力を分析し、**必ず**以下の JSON 形式で回答してください。
JSON 以外のテキストは一切含めないでください。

出力形式:
{
  "category": "カテゴリ名（A / B / C のいずれか）",
  "confidence": 0.0〜1.0の数値,
  "reasoning": "判断理由を1文で"
}

入力:
{{input_text}}
```

### 配列形式

```
以下のテキストからエンティティを抽出し、JSON 配列で返してください。

出力形式:
[
  {
    "entity": "エンティティ名",
    "type": "PERSON | ORG | LOCATION | DATE",
    "position": "テキスト内の出現位置（文番号）"
  }
]

テキスト:
{{input_text}}
```

### ネスト形式

```
以下の文書を分析し、構造化された JSON で返してください。

出力形式:
{
  "summary": "全体要約（100文字以内）",
  "sections": [
    {
      "title": "セクション名",
      "key_points": ["要点1", "要点2"],
      "sentiment": "positive | neutral | negative"
    }
  ],
  "metadata": {
    "word_count": 数値,
    "language": "ja | en",
    "topics": ["トピック1", "トピック2"]
  }
}
```

## XML 出力テンプレート（Claude 推奨）

### 基本形

```
以下の入力を分析し、XML タグで構造化して回答してください。

<analysis>
  <category>カテゴリ名</category>
  <confidence>0.0〜1.0</confidence>
  <reasoning>判断理由</reasoning>
</analysis>

入力:
<input>
{{input_text}}
</input>
```

### 思考プロセス + 回答分離（CoT 用）

```
以下の問題についてステップバイステップで考えてください。

思考プロセスは <thinking> タグ内に記述し、
最終回答は <answer> タグ内に記述してください。

<thinking>
（ここに推論過程を記述）
</thinking>

<answer>
（ここに最終回答のみを記述）
</answer>
```

## Markdown 出力テンプレート

### レポート形式

```
以下のデータを分析し、Markdown レポートを作成してください。

## 出力形式

### 1. エグゼクティブサマリー
（3文以内で結論を記述）

### 2. 分析結果
| 指標 | 値 | 評価 |
|:---|:---|:---|
| （指標名） | （数値） | （良好/注意/要改善） |

### 3. 推奨アクション
1. （最優先アクション）
2. （次のアクション）
3. （長期的アクション）

### 4. リスクと注意点
- （リスク1）
- （リスク2）
```

### 比較分析形式

```
以下の2つの選択肢を比較分析してください。

## 出力形式

### 比較サマリー
| 観点 | 選択肢A | 選択肢B |
|:---|:---|:---|
| コスト | | |
| 品質 | | |
| 導入期間 | | |

### 推奨
（どちらを推奨するか + 理由を2文で）

### 条件分岐
- Aを選ぶべき場合: （条件）
- Bを選ぶべき場合: （条件）
```

## CSV 出力テンプレート

```
以下のテキストからデータを抽出し、CSV 形式で出力してください。
ヘッダ行を含め、値はダブルクォートで囲んでください。

出力形式:
"name","category","value","date"
"項目名","カテゴリ","数値","YYYY-MM-DD"

テキスト:
{{input_text}}
```

## 出力制御の共通テクニック

### 出力開始文字列の強制

| 手法 | 適用モデル | 実装 |
|:---|:---|:---|
| **Prefix 強制** | Claude (API) | assistant メッセージの先頭に `{` や `<` を含める |
| **開始トリガー** | 全モデル | 「回答は必ず `{` から始めてください」 |
| **response_format** | GPT (API) | `response_format: { type: "json_schema" }` |
| **MIME type** | Gemini (API) | `response_mime_type: "application/json"` |

### 出力長の制御

| 指定方法 | 精度 | 例 |
|:---|:---|:---|
| **文字数指定** | 中 | 「200文字以内で回答」 |
| **文数指定** | 高 | 「3文で回答」 |
| **段落数指定** | 高 | 「2段落で回答」 |
| **箇条書き数指定** | 最高 | 「5つの箇条書きで回答」 |
| **max_tokens** | API 強制 | パラメータで物理的に制限 |

> **ベストプラクティス**: 「文字数」よりも「文数」「箇条書き数」で指定する方が LLM は遵守しやすい。
