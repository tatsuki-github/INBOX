# モデル別最適化ガイド

> Claude / GPT / Gemini 各モデルの特性と、プロンプト設計での最適化テクニック。

---

## Claude（Anthropic）

### 特性

| 特性 | 詳細 |
|:---|:---|
| **コンテキストウィンドウ** | 200K トークン（Claude 3.5 Sonnet） |
| **得意分野** | 長文理解、指示遵守、XML 構造の解析、コード生成 |
| **System Prompt** | 強く尊重される。長い System Prompt も有効 |
| **出力制御** | XML タグ指定 + Prefix による強制が最も効果的 |

### 最適化テクニック

| テクニック | 実装 | 効果 |
|:---|:---|:---|
| **XML タグ構造化** | `<context>`, `<task>`, `<rules>` でセクション分離 | 指示の解釈精度向上 |
| **Prefix 強制** | assistant メッセージに `{` を含めて JSON 出力を強制 | フォーマット遵守率 95%+ |
| **Extended Thinking** | `thinking` パラメータで内部推論を明示化 | 複雑な推論タスクでの精度向上 |
| **プロンプトキャッシュ** | 静的な System Prompt をキャッシュ | コスト 90% 削減、レイテンシ 85% 削減 |
| **長文コンテキスト活用** | 200K のウィンドウを活かし、大量の参考資料を直接挿入 | 外部検索(RAG)不要のケースが増える |

### Claude 固有の注意点

- `<instructions>` タグは特別扱いされる — 重要な指示はこのタグ内に
- thinking ブロック内にプロンプトの一部が露出するリスクあり（API 利用時）
- マルチターン会話では直前のターンが最も影響力が高い

## GPT-4o / GPT-4（OpenAI）

### 特性

| 特性 | 詳細 |
|:---|:---|
| **コンテキストウィンドウ** | 128K トークン（GPT-4o） |
| **得意分野** | Markdown 構造の理解、JSON mode、関数呼び出し |
| **System Prompt** | Markdown 形式の構造化が効果的。極端に長いと指示遵守率が低下 |
| **出力制御** | `response_format` による JSON Schema 強制が最も効果的 |

### 最適化テクニック

| テクニック | 実装 | 効果 |
|:---|:---|:---|
| **JSON mode** | `response_format: { type: "json_object" }` | JSON 出力を 100% 保証 |
| **Structured Outputs** | `response_format: { type: "json_schema", json_schema: {...} }` | スキーマ遵守を 100% 保証 |
| **Function calling** | tools パラメータでツール定義 | 外部ツール連携の標準方式 |
| **Markdown 構造化** | `## セクション`, `- リスト` で階層化 | 指示解釈の精度向上 |
| **Seed パラメータ** | `seed: 123` で出力の再現性を向上 | 同一入力での一貫性向上 |

### GPT 固有の注意点

- System Prompt に XML タグを使うと Claude ほど効果がない
- `temperature: 0` でも完全な再現性は保証されない（seed 併用推奨）
- 長いプロンプトでは中間部分の指示が無視されやすい（"Lost in the Middle" 問題）

## Gemini（Google）

### 特性

| 特性 | 詳細 |
|:---|:---|
| **コンテキストウィンドウ** | 1M トークン（Gemini 1.5 Pro）、2M トークン（Gemini 2.0） |
| **得意分野** | マルチモーダル（画像・音声・動画）、超長文理解 |
| **System Prompt** | `system_instruction` パラメータで指定 |
| **出力制御** | MIME type 指定 + JSON Schema 対応 |

### 最適化テクニック

| テクニック | 実装 | 効果 |
|:---|:---|:---|
| **マルチモーダル入力** | 画像・音声・動画を直接入力 | OCR / 音声認識不要のワンショット処理 |
| **超長文コンテキスト** | 1M トークンのウィンドウを活用 | 書籍丸ごと 1 回のコンテキストに投入可能 |
| **JSON 応答制御** | `response_mime_type: "application/json"` | JSON 出力を強制 |
| **Grounding** | Google 検索との統合 | リアルタイム情報を回答に反映 |

### Gemini 固有の注意点

- Safety filters がデフォルトで有効 — 医療・法律系のプロンプトでブロックされやすい
- 日本語の指示遵守は Claude / GPT に比べて若干不安定（改善傾向）
- マルチモーダルの精度はモダリティ（画像 > 音声 > 動画）で差がある

## モデル非依存のベストプラクティス

| プラクティス | 説明 |
|:---|:---|
| **指示文は対象言語で書く** | 日本語出力なら日本語で指示。英語プロンプト+日本語出力は一貫性が下がる |
| **重要な指示は先頭と末尾に** | 中間部に埋もれる指示は無視されやすい（Primacy / Recency 効果） |
| **否定形より肯定形** | 「〜しないで」→「〜してください」。否定形は解釈がブレやすい |
| **曖昧語の完全排除** | 「適切に」「良い」「十分な」→ 数値や具体条件に置換 |
| **区切りの明示** | XML タグ / Markdown 見出し / デリミタでセクションを明確に分離 |
