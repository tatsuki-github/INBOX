# Phase 6 レビュー基準詳細

implementation-flow Phase 6 で適用するクリティカルレビューの詳細基準。
review スキルの Part A（ドキュメント）+ Part B（コード）を Phase 1-5 の成果物に適用する。

---

## 重要度定義

| レベル | 定義 | 対応 |
|:-------|:-----|:-----|
| **Critical** | リリースブロッカー。セキュリティ脆弱性、データ損失リスク、クラッシュ | 即時修正必須 |
| **Major** | 品質ブロッカー。要件未充足、型安全性違反、UX 重大問題 | 修正必須 |
| **Minor** | 改善推奨。命名改善、パフォーマンス最適化の余地、可読性向上 | 修正推奨 |
| **Info** | 参考情報。代替案の提示、将来の拡張ポイント | 記録のみ |

## 承認条件

- **Critical = 0 件**（未修正の Critical が 1 件でもあれば Rejected）
- **Major = 0 件**（全件修正済み）
- Minor / Info は記録するが、承認をブロックしない

## Part A: 設計ドキュメントレビュー

### A-1: 要件カバレッジ

Phase 1 で定義した受け入れ条件と、Phase 5 の実装を突き合わせる。

| チェック項目 | 判定基準 | 違反時の重要度 |
|:------------|:---------|:--------------|
| 全受け入れ条件が実装されている | 1 対 1 対応を確認 | Major |
| スコープ外の機能が混入していない | Out of Scope に含まれていない | Minor |
| 暗黙の要件が見落とされていない | エラーケース、エッジケースを含む | Major |
| **既存振る舞い退行なし**（`extend` Lite Path のみ） | Phase 1 回帰テスト要件が Green。既存 API/UX の契約が維持されている | Major |

### A-2: 章間整合性

Phase 1-5 の全ドキュメント間に矛盾がないか。

| チェック項目 | 判定基準 | 違反時の重要度 |
|:------------|:---------|:--------------|
| Phase 2 のユーザーフローと Phase 5 の実装が一致 | 全ステップの対応確認 | Major |
| Phase 3 の ADR 判断が Phase 5 で遵守されている | ADR の Decision と実装の一致 | Major |
| Phase 4 のデザイントークンが Phase 5 で使用されている | CSS 変数の一致確認 | Major |
| Phase 2 の応答性要件が Phase 5 で考慮されている | ローディング状態の実装確認 | Minor |

### A-3: 数値・データの妥当性

| チェック項目 | 判定基準 | 違反時の重要度 |
|:------------|:---------|:--------------|
| 応答性目標値に根拠がある | Doherty Threshold 等の引用 | Minor |
| ブレイクポイント値が妥当 | 768px / 1024px 等の業界標準 | Minor |
| カラーコントラスト比が正確 | WCAG AA 4.5:1 の計算確認 | Major |

### A-4: 可読性

| チェック項目 | 判定基準 | 違反時の重要度 |
|:------------|:---------|:--------------|
| 第三者が設計意図を理解できる | 専門用語に説明がある | Minor |
| ADR の根拠が具体的 | 「〜のため」だけでなく具体的なデータ/比較 | Minor |

### A-5: Docs ↔ Code 整合

Docs Sync（QE5-7）が有効なワークフローで、永続ドキュメント（`specs/` / `docs/`）と実装の一致を検証する。無効時は N/A。

| チェック項目 | 判定基準 | 違反時の重要度 |
|:------------|:---------|:--------------|
| 受け入れ条件が doc に反映されている | Phase 1 の各条件が対応 doc に記述されている | Major |
| 実装と doc の API/UX 記述が一致 | パス・メソッド・レスポンス・画面動作がコードと一致 | Major |
| インデックスが最新 | `INVENTORY.md` または README の目次に新規 doc / 削除ルートが反映 | Minor |
| 幽霊仕様がない | 削除済みコードの doc が「履歴」注記なしに現行仕様として残っていない | Major |
| 正本が一意（併存時） | `specs/` と `docs/` 併存時、同一内容の二重メンテではなくリンクで接続 | Minor |
| ADR と実装が一致 | 永続 ADR の Decision が Phase 5 実装と一致 | Major |

**R5 での簡易チェック**: QE5-7 レポートの整合確認チェックリストが全て完了していること。

## Part B: コードレビュー

### B-1: Semantic Drift（設計と実装の乖離）

実装が Phase 1-4 の設計から逸脱していないか。

| チェック項目 | 判定基準 | 違反時の重要度 |
|:------------|:---------|:--------------|
| コンポーネント名が Phase 3 の設計と一致 | 命名の一致確認 | Minor |
| ファイル構成が Phase 3 の計画と一致 | ディレクトリ構造の確認 | Major |
| データフローが Phase 3 の設計と一致 | 依存方向の確認 | Major |
| UI が Phase 4 の仕様を満たしている | 状態・バリアント・レスポンシブの確認 | Major |

### B-2: Accounting Integrity（数値処理の正確性）

| チェック項目 | 判定基準 | 違反時の重要度 |
|:------------|:---------|:--------------|
| 通貨計算に浮動小数点を使用していない | Decimal ライブラリ or 整数演算 | Critical |
| 丸め処理の方針が統一されている | 切り上げ/切り捨て/四捨五入の明示 | Major |
| 集計値の精度が保証されている | 合計と明細の一致確認 | Major |

### B-3: Edge Case Attack

| チェック項目 | 判定基準 | 違反時の重要度 |
|:------------|:---------|:--------------|
| Null / Undefined の処理 | 型ガードまたは Optional Chaining | Major |
| 空配列 / 空文字列の処理 | 空の状態が UI で表現されている | Major |
| 境界値の処理 | 0、負数、最大値のハンドリング | Major |
| 並行操作の処理 | ダブルクリック防止、楽観的更新の競合 | Major |
| 不正入力の処理 | XSS 文字列、SQL インジェクション文字列 | Critical |

### B-4: Privacy Violation

| チェック項目 | 判定基準 | 違反時の重要度 |
|:------------|:---------|:--------------|
| ログに PII（個人情報）が含まれていない | email、氏名、住所等のマスク | Critical |
| エラーメッセージに内部情報がない | スタックトレース、DB スキーマ等 | Critical |
| 機密情報がフロントエンドに露出していない | API キー、シークレット | Critical |

### B-5: Performance

| チェック項目 | 判定基準 | 違反時の重要度 |
|:------------|:---------|:--------------|
| N+1 問題がない | ループ内 API 呼び出しの排除 | Major |
| 適切なメモ化 | `useMemo` / `useCallback` の適切な使用 | Minor |
| 不要な再レンダリングがない | Props の安定性、Context の分割 | Minor |
| バンドルサイズの考慮 | Dynamic Import / Code Splitting | Minor |

### B-6: Test Coverage

[test](../../test/SKILL.md) スキルの 4 本柱と [review](../../review/SKILL.md) B-6 基準に準拠。

| チェック項目 | 判定基準 | 違反時の重要度 |
|:------------|:---------|:--------------|
| ドメイン層にテストがある | utils/services の公開関数に Red ファーストの単体テスト | Major |
| 正常系 + 異常系 | エラー状態・例外パスがテストされている | Major |
| エッジケース | null, 0, 空文字列, 最大値等の境界値 | Major |
| 受け入れ条件のテスト対応 | Phase 1 テストマッピングの全項目がテストで検証されている | Major |
| 振る舞いベース | 実装詳細ではなく観察可能な振る舞いを検証 | Major |
| カバレッジ 80% 以上 | **ドメイン層（utils/services）を優先**。UI Presentational まで 80% 強制はしない | Major |
| vitest 全件パス | Red が残っていない | Critical |
| 過剰モック・偽陽性 | スタブ呼び出し検証なし、内部通信のモック化なし | Major |

### B-7: Build & Lint

[typescript-implementation-guide.md](typescript-implementation-guide.md) の「検証実行（verify）規約」に準拠。QE5 / QE6 でシェル実行済みであること。

| チェック項目 | 判定基準 | 違反時の重要度 |
|:------------|:---------|:--------------|
| backend build 成功 | `backend/` に変更がある場合、`npm run build` が exit 0 | Critical |
| frontend lint 成功 | `frontend/` に変更がある場合、`npm run lint` が exit 0 | Critical |
| frontend build 成功 | `frontend/` に変更がある場合、`npm run build` が exit 0 | Critical |
| 検証コマンド未実行 | QE5-0 / QE5-4 退行検証 / QE6-0 のいずれかが欠落、または口頭合格のみ | Critical |
| 対象パッケージの誤判定 | Phase 0 記録と `git diff` が矛盾（例: backend のみ記録だが frontend も変更） | Major |
