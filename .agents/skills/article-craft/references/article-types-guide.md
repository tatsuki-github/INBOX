## 1. ハウツー記事

### 概要

| 項目 | 説明 |
|:---|:---|
| **目的** | 読者に具体的な手順を教え、行動を起こさせる |
| **読者の期待** | 「これを読めば自分にもできる」と思える |
| **成功基準** | 読者が記事の手順を再現できる |

### 構成テンプレート

```markdown
# [タイトル]: [数字] + [ベネフィット] の [方法]

## リード文
- 読者の課題に共感 → この記事で解決できることを宣言

## 前提・準備
- 必要な道具・環境・前提知識

## ステップ 1: [アクション名]
- 何をするか（手順）
- なぜそうするか（理由）
- 注意点・Tips

## ステップ 2: [アクション名]
...

## ステップ N: [アクション名]
...

## よくある失敗と対策
- 失敗パターン → 原因 → 対策

## まとめ
- キーポイントの再確認
- 次のステップ（CTA）
```

### タイトル例

| ✅ Good | ❌ Bad | 理由 |
|:---|:---|:---|
| 「初心者でもできる！Git の使い方 5 ステップ」 | 「Git について」 | 具体性 + 数字 + ベネフィット |
| 「30 分で完成する自動テスト環境の構築手順」 | 「テスト環境の話」 | 所要時間 + 成果物が明確 |

## 2. 解説・入門記事

### 概要

| 項目 | 説明 |
|:---|:---|
| **目的** | 概念・仕組み・背景を理解させる |
| **読者の期待** | 「なるほど、そういうことか」と腹落ちする |
| **成功基準** | 読者が他者に説明できるレベルで理解する |

### 構成テンプレート

```markdown
# [概念名] とは？[読者のベネフィット]

## リード文
- 「○○って聞いたことはあるけど、よくわからない」に応える

## ○○ とは何か（概要）
- 一言での定義
- 身近な例えでイメージを持たせる

## なぜ ○○ が重要なのか
- 背景・文脈
- 使わない場合のリスク

## ○○ の仕組み（詳細）
- 構成要素の説明
- 図やフローチャートの活用

## 具体的な活用例
- ユースケース 1
- ユースケース 2

## よくある誤解
- 誤解 → 正しい理解

## まとめ
- 3 行で要点を再確認
- さらに学ぶためのリソース
```

## 3. オピニオン記事

### 概要

| 項目 | 説明 |
|:---|:---|
| **目的** | 自分の主張を論理的に伝え、読者の思考を促す |
| **読者の期待** | 「新しい視点を得た」「考えるきっかけになった」 |
| **成功基準** | 主張が明確で、根拠に説得力がある |

### 構成テンプレート

```markdown
# [主張を含むタイトル]

## リード文
- 問題提起 or 意外な事実で注意を引く

## 私の主張
- 一文で主張を明示する（曖昧にしない）

## 根拠 1: [論点]
- データ / 事例 / 経験に基づく論証

## 根拠 2: [論点]
...

## 根拠 3: [論点]
...

## 想定される反論への応答
- 「しかし〜ではないか」→ 「それは〜だからだ」

## 結論
- 主張の再確認
- 読者への問いかけ（思考を促す CTA）
```

### 注意点

| 注意点 | 対策 |
|:---|:---|
| 主張が曖昧 | 冒頭で「私は○○だと考える」と明言する |
| 根拠が弱い | データ・事例・引用で裏付ける（最低 3 つ） |
| 一方的になる | 反論を想定し、誠実に応答するセクションを設ける |
| 攻撃的になる | 「人」ではなく「意見」を批判する |

## 4. ケーススタディ記事

### 概要

| 項目 | 説明 |
|:---|:---|
| **目的** | 実体験を通じて学びを共有し、読者の意思決定を支援する |
| **読者の期待** | 「同じ状況で参考にできる」と思える |
| **成功基準** | 背景→施策→結果→学びが具体的に追体験できる |

### 構成テンプレート

```markdown
# [成果] を実現した [施策] の全記録

## リード文
- 結果のハイライト（数値があれば提示）

## 背景
- プロジェクト / チーム / 状況の説明
- なぜこの取り組みが必要だったか

## 課題
- 具体的な問題点（数値化できるものは数値で）

## 施策
- 何をしたか（時系列 or 施策別）
- なぜその方法を選んだか

## 結果
- 定量的な成果（Before / After）
- 定性的な変化

## 学びと反省
- うまくいった要因
- 改善すべきだった点
- 再現する際のアドバイス

## まとめ
- 他の読者が活かせるポイント
```

## 5. リスト記事

### 概要

| 項目 | 説明 |
|:---|:---|
| **目的** | 複数の情報を整理して一覧性高く提供する |
| **読者の期待** | 「必要な情報がまとまっている」と思える |
| **成功基準** | 各項目が統一フォーマットで比較しやすい |

### 構成テンプレート

```markdown
# [対象] おすすめ [数字] 選 — [選定基準]

## リード文
- 選定基準の説明

## 選定基準
- 基準 1 / 基準 2 / 基準 3

## 1. [項目名]
- 概要: ...
- 特徴: ...
- おすすめの人: ...

## 2. [項目名]
...

## N. [項目名]
...

## 比較表（まとめ）
| 項目 | 基準 1 | 基準 2 | 基準 3 |
...

## まとめ
- 目的別の推奨
```

### 注意点

| 注意点 | 対策 |
|:---|:---|
| 項目のフォーマットが不統一 | テンプレート（概要 / 特徴 / 推奨場面）を事前に決め、全項目で統一する |
| 順序に根拠がない | 重要度順、カテゴリ順、初心者→上級者の順など、明確なルールを設ける |
| 選定基準が不明 | 冒頭で「何を基準に選んだか」を明示する |

## 6. 比較記事

### 概要

| 項目 | 説明 |
|:---|:---|
| **目的** | 複数の選択肢を公平に比較し、読者の意思決定を支援する |
| **読者の期待** | 「自分の状況に合う選択肢がわかる」 |
| **成功基準** | 評価軸が明確で、読者が自分で判断できる |

### 構成テンプレート

```markdown
# [候補 A] vs [候補 B] — [判断軸] で徹底比較

## リード文
- 比較の背景と読者のメリット

## 比較サマリ
| 評価軸 | 候補 A | 候補 B | 候補 C |
|:---|:---:|:---:|:---:|
| ... | ... | ... | ... |

## 評価軸 1: [軸名]
- 候補 A: ...
- 候補 B: ...

## 評価軸 2: [軸名]
...

## こんな人には ○○ がおすすめ
- ケース A → 候補 A
- ケース B → 候補 B

## まとめ
```

## 9. まとめ・振り返り記事

### 構成テンプレート

```markdown
# [期間] の振り返り — [ハイライト]

## リード文
- 振り返る期間と目的

## 背景・目標
- 期初に立てた目標

## 成果
- 定量的な成果
- 定性的な成果

## 課題・反省
- うまくいかなかったこと
- 原因分析

## 学び
- 次に活かせること

## 次のアクション
- 具体的な改善計画
```

## 媒体別のカスタマイズ

| 媒体 | 推奨文字数 | 特徴 | 注意点 |
|:---|:---:|:---|:---|
| **Zenn** | 3000〜8000 | 技術寄り、Markdown 完全対応、コードブロック活用 | 技術的な正確性を重視 |
| **Qiita** | 2000〜6000 | 技術ナレッジ共有、タグ文化 | 実用性・再現性を重視 |
| **note** | 1500〜5000 | 多ジャンル、エッセイ〜解説まで | 読みやすさ・共感性を重視 |
| **社内ブログ** | 1000〜3000 | 社内向け、背景共有不要 | 簡潔さを重視 |
| **はてなブログ** | 2000〜6000 | 多ジャンル、SEO 効果あり | タイトルと見出しの SEO を意識 |
| **Medium** | 1500〜4000 | 英語圏、グローバル発信 | 英語の自然さを重視 |
