# ドメイン固有リスク — 必須確認事項

> req-elicit の Step 1・Step 4・Step 6 で参照するドメイン別のリスクと必須確認事項。
> 見落とすと後工程（設計・開発・リリース後）で致命的な問題になる項目を集約。

---

## EC / 決済

| リスク | 必須確認事項 | 見落とした場合のコスト |
|:---|:---|:---|
| **PCI DSS 非準拠** | カード情報を自社で保持するか？準拠の要件はあるか？ | 法的ペナルティ・サービス停止 |
| **決済失敗時の補償** | 二重課金・未課金の検知・補正フローは？ | 顧客クレーム・返金対応コスト |
| **在庫の競合** | 同時購入時の在庫競合（Race Condition）をどう扱うか？ | 在庫マイナス・顧客への謝罪 |
| **消費税・軽減税率** | 商品カテゴリによる税率の違いを管理するか？ | 税務リスク |
| **特定商取引法** | 表示義務（返品ポリシー・事業者情報等）の要件は？ | 法的リスク |
| **不正注文対策** | 不正クレジット利用の検知・ブロック機能は必要か？ | チャージバック損失 |

## 医療 / ヘルスケア

| リスク | 必須確認事項 | 見落とした場合のコスト |
|:---|:---|:---|
| **個人情報保護法・医療法** | 患者情報の取扱いに法的規制はあるか？ | 行政処分・信頼失墜 |
| **電子カルテ標準** | HL7 FHIR・SS-MIX2 等の標準への準拠は必要か？ | 連携不能・再開発 |
| **データの正確性** | 誤情報が患者の健康被害につながるリスクの評価は？ | 医療事故・訴訟リスク |
| **アクセスログ** | 誰が患者情報にアクセスしたかの監査ログは必須か？ | コンプライアンス違反 |
| **第三者提供** | 患者同意なしのデータ外部提供の禁止ルールは？ | 法的リスク |

---

## 金融 / 会計 / FinTech

| リスク | 必須確認事項 | 見落とした場合のコスト |
|:---|:---|:---|
| **金融商品取引法・資金決済法** | 金融サービス業の登録・届出が必要か？ | 無登録営業の罰則 |
| **AML（マネロン対策）** | 本人確認（KYC）・取引監視の要件はあるか？ | 金融庁処分 |
| **監査証跡** | 全取引のログ保存期間は？（一般的に 7〜10 年） | 監査対応不能 |
| **データ整合性** | 金額・残高の二重計上・不整合の検知方法は？ | 財務リスク |
| **FISC 安全対策基準** | 金融機関向けシステムの場合、準拠が必要か？ | 調達条件不達成 |

## 社内ツール / 業務システム

| リスク | 必須確認事項 | 見落とした場合のコスト |
|:---|:---|:---|
| **認証・SSO** | Active Directory / Google Workspace 等との SSO は必要か？ | 別途パスワード管理コスト |
| **既存システム依存** | 連携する基幹システムの API 仕様・制限は？ | 連携不能・設計やり直し |
| **データ移行** | 既存 Excel / DB からのデータ移行の品質・量は？ | 移行工数の過小見積 |
| **権限設計の複雑化** | 部署・役職・プロジェクト単位の複雑な権限が必要か？ | RBAC 設計の手戻り |
| **オフライン対応** | 工場・倉庫など通信が不安定な環境で使うか？ | 実運用不能 |
| **端末の多様性** | PC/タブレット/スマホ/ハンディ等の複数端末対応が必要か？ | レスポンシブ対応漏れ |

## AI / LLM / チャットボット

| リスク | 必須確認事項 | 見落とした場合のコスト |
|:---|:---|:---|
| **機密情報の外部送信** | 社内データを外部 LLM API に送信してよいか？ | 情報漏洩・規約違反 |
| **ハルシネーション対策** | 誤情報を回答した場合の責任範囲・免責表示は？ | 信頼失墜・クレーム |
| **RAG のソース管理** | ナレッジベースの更新権限・鮮度管理は誰が担うか？ | 古い情報の回答 |
| **ユーザーの悪用** | プロンプトインジェクション・不適切利用への対策は？ | セキュリティインシデント |
| **コスト管理** | LLM API の利用コスト上限・トークン数管理の仕組みは？ | 予期しない高額請求 |
| **回答精度の計測** | 精度をどのように評価し、改善するか？ | 品質管理不能 |

## データ基盤 / BI / 分析

| リスク | 必須確認事項 | 見落とした場合のコスト |
|:---|:---|:---|
| **KPI 定義の曖昧さ** | 「売上」「ユーザー数」等の定義が部門間で一致しているか？ | 数値の不一致でダッシュボードが信頼されない |
| **データソースの品質** | ソースデータに欠損・重複・外れ値があるか？対処方針は？ | 集計誤りによる経営判断ミス |
| **データの鮮度** | リアルタイム要件か？バッチ更新でよいか？ | 設計コストの大幅増 |
| **アクセス制御** | 誰がどのデータを見られるか？部署・役職での分離は？ | 機密情報の漏洩 |
| **ストレージコスト** | データ量の成長予測と保持期間からストレージコストを試算したか？ | 予算超過 |
| **既存 ETL との競合** | 既存のデータパイプラインと新システムの役割分担は？ | 二重管理・不整合 |

## モバイルアプリ

| リスク | 必須確認事項 | 見落とした場合のコスト |
|:---|:---|:---|
| **OS バージョン対応範囲** | 最低限サポートする iOS/Android バージョンは？ | 端末対応漏れ |
| **App Store 審査** | App Store / Google Play の審査ポリシーに抵触する機能はあるか？ | リジェクト・リリース遅延 |
| **プッシュ通知の同意** | GDPR・個人情報保護法のもとでのオプトイン設計は？ | 法的リスク |
| **バッテリー・通信量** | バックグラウンド処理によるバッテリー消費・データ通信量の制約は？ | ユーザーの削除 |
| **アップデート強制** | 旧バージョンのサポート切り・強制アップデートの方針は？ | API 互換性維持コスト |
| **オフラインデータ同期** | オフライン中に発生したデータの競合（Conflict）をどう解決するか？ | データ不整合 |
