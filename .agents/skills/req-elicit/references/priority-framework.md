# 優先度フレームワーク — 質問の分類・品質基準

> req-elicit の Step 7 で適用する、質問の優先度判定と品質チェックの基準集。

---

## 優先度 S/A/B の判定基準

### 優先度 S（最重要）— 先に回答が必要

「この回答がなければ設計の方向性が決まらない」質問。
ヒアリング冒頭の 15〜30 分で必ず確認する。

| 判定条件 | 例 |
|:---|:---|
| スコープ境界を決定する | 「フェーズ1の必須機能とフェーズ2以降の機能を分けてください」 |
| ビルドするかしないかを決定する | 「既存システムの機能拡張ですか？新規開発ですか？」 |
| アーキテクチャ選択を左右する | 「社内機密データを外部 LLM に送信してよいですか？」 |
| 法的・コンプライアンスリスクに直結する | 「個人情報（氏名・住所・決済情報）を扱いますか？」 |
| 成功基準を定義する | 「どうなればこのシステムは成功と言えますか？指標はありますか？」 |

**目安**: 3〜5 問に絞る。6 問以上は絞り込み不足。

---

### 優先度 A（重要）— 基本設計に必要

「この回答がないと基本設計・技術選定が始まらない」質問。
初回ヒアリング内で確認する。優先度 S への回答後に進める。

| サブカテゴリ | 含める質問の種類 |
|:---|:---|
| **A — 機能要件** | ユースケース・権限・操作フロー・通知・例外処理 |
| **A — 非機能要件** | 性能・可用性・セキュリティ・スケール・アクセシビリティ |
| **A — データ要件** | データソース・出力形式・連携・マスタ・マイグレーション |

**目安**: 15〜25 問。多すぎる場合はサブカテゴリ内で絞る。

---

### 優先度 B（確認）— あれば精度が上がる

「後でも回答可能だが、決定しておくと設計品質が上がる」質問。
初回ヒアリング後のフォローアップ、または第 2 回ヒアリングで確認する。

| サブカテゴリ | 含める質問の種類 |
|:---|:---|
| **B — 制約・前提** | 技術スタック・予算・既存資産・コンプライアンス |
| **B — 将来性・拡張性** | フェーズ2以降・スケール予測・運用体制 |

**目安**: 5〜10 問。

---

## 質問の品質チェック基準

### よい質問の 4 条件

| 条件 | 説明 | チェック方法 |
|:---|:---|:---|
| **具体的** | 回答者が迷わず答えられる | 「何が重要ですか？」→ NG。「最も優先度の高い機能を3つ挙げてください」→ OK |
| **単一焦点** | 1 問に 1 つの質問のみ | 「と」「また」「それと」が入っていたら分割する |
| **非誘導** | 特定の回答を前提としない | 「React を使いますよね？」→ NG。「フロントエンドのフレームワークの指定はありますか？」→ OK |
| **層の一致** | ビジネス・ロジック・データの層を混在しない | 機能要件に「DBのテーブル設計は？」を入れない |

### 質問アンチパターン

| アンチパターン | 例 | 修正案 |
|:---|:---|:---|
| **抽象質問** | 「何が大事ですか？」 | 「優先度の高い機能を 3 つ以内で教えてください」 |
| **複合質問** | 「予算と期日と担当者は？」 | 3 つの質問に分割する |
| **技術実装質問** | 「DBのスキーマはどうしますか？」 | 要件フェーズでは不問（後工程） |
| **誘導質問** | 「マイクロサービスで作りますよね？」 | 「アーキテクチャの指定はありますか？」 |
| **二択固定** | 「AかBどちらですか？」（Cがある場合） | 「どのようなアプローチを想定していますか？」 |
| **前提の押し付け** | 「クラウドを使うと思いますが〜」 | 「インフラ（クラウド/オンプレ）の指定はありますか？」 |

---

## 質問数のガイドライン

| ヒアリング形式 | 推奨質問数 | 構成 |
|:---|:---|:---|
| **初回キックオフ（60 分）** | S: 3〜5 + A: 10〜15 | 合計 15〜20 問 |
| **フォローアップ（30 分）** | A: 残り + B: 5〜10 | 合計 10〜15 問 |
| **書面回答シート** | S + A + B 全量 | 25〜40 問 |

---

## 優先度 S の質問テンプレート集

どんなドメインでも適用できる汎用的な優先度 S 質問:

```
1. このシステムを使って解決したい「最も大きな課題」は何ですか？
2. どうなればこのプロジェクトは成功と言えますか？指標はありますか？
3. フェーズ1で必ず完成させる機能と、後回しにできる機能を分けてください。
4. 既存のシステム・ツールで「必ず連携が必要なもの」はありますか？
5. 個人情報・機密情報を扱いますか？法規制（GDPR・個人情報保護法等）の対象ですか？
```
