# コードスメルカタログ

> Fowler の 22 コードスメルカテゴリを、検出シグネチャ・影響度・推奨パターンとともに整理したリファレンス。

---

## 1. 関数・メソッドレベルのスメル

### Long Method（長すぎる関数）

| 項目 | 内容 |
|:---|:---|
| **定義** | 処理が長すぎて一読で理解できない関数・メソッド |
| **検出シグネチャ** | 関数行数が 20 行超（コンテキストによる。複雑なアルゴリズムは例外） |
| **影響** | 可読性低下、テスト困難、変更リスク高 |
| **推奨パターン** | Extract Function, Replace Temp with Query, Decompose Conditional |
| **誤検出注意** | アルゴリズムの可読性のために長くしている場合は除外 |

### Long Parameter List（長すぎる引数リスト）

| 項目 | 内容 |
|:---|:---|
| **定義** | 引数が多すぎて呼び出し側が複雑になる関数 |
| **検出シグネチャ** | 引数 4 個超 |
| **影響** | 呼び出し元の複雑化、順序依存バグのリスク |
| **推奨パターン** | Introduce Parameter Object, Preserve Whole Object |

### Duplicate Code（重複コード）

| 項目 | 内容 |
|:---|:---|
| **定義** | 同一 or 類似のコードが複数箇所に存在する |
| **検出シグネチャ** | 3 行以上の同一処理が 2 箇所以上 |
| **影響** | 変更時に複数箇所を修正する必要があり、修正漏れが発生しやすい |
| **推奨パターン** | Extract Function, Pull Up Method, Form Template Method |

### Dead Code（デッドコード）

| 項目 | 内容 |
|:---|:---|
| **定義** | 呼び出されない / 到達不能なコード |
| **検出シグネチャ** | grep で呼び出し元なし、コメントアウトされたコード、unreachable なブランチ |
| **影響** | 読み手の混乱、誤ったメンテナンス |
| **推奨パターン** | Remove Dead Code |

### Speculative Generality（過剰な汎化）

| 項目 | 内容 |
|:---|:---|
| **定義** | 「将来必要かも」で追加された未使用の汎化・抽象化 |
| **検出シグネチャ** | 実装クラスが 1 つだけの abstract class / interface、使われないフック |
| **影響** | 不必要な複雑さ |
| **推奨パターン** | Inline Class, Collapse Hierarchy, Remove Middle Man |

## 2. クラス・モジュールレベルのスメル

### Large Class / God Class（巨大クラス）

| 項目 | 内容 |
|:---|:---|
| **定義** | 1 クラスが多数の責務を持つ |
| **検出シグネチャ** | クラス行数 500 行超、フィールド 10 個超、関係のない責務が混在 |
| **影響** | 変更のたびに予期しない副作用、テスト困難 |
| **推奨パターン** | Extract Class, Move Method, Move Field |
| **責務の見極め方** | 「このクラスのメソッドが変わる理由は何か？」を問い、同じ理由で変わるものをまとめる |

### Feature Envy（他クラスへの過剰な依存）

| 項目 | 内容 |
|:---|:---|
| **定義** | あるメソッドが自クラスよりも他クラスのデータ/メソッドを多用する |
| **検出シグネチャ** | `other.fieldA`, `other.fieldB`, `other.methodC()` が同一メソッド内に 3 回以上 |
| **影響** | 変更が伝播する、メソッドが本来あるべきクラスにない |
| **推奨パターン** | Move Method（メソッドをデータのあるクラスへ移動） |

### Data Clumps（データの塊）

| 項目 | 内容 |
|:---|:---|
| **定義** | 常に一緒に渡されるデータグループ |
| **検出シグネチャ** | 3 個以上の変数が常にペアで関数の引数・フィールドに出現 |
| **影響** | データのグルーピングができていない設計上の匂い |
| **推奨パターン** | Introduce Parameter Object, Extract Class |

### Divergent Change（分散した変更理由）

| 項目 | 内容 |
|:---|:---|
| **定義** | 1 クラスが複数の異なる理由で変更される（SRP 違反） |
| **検出シグネチャ** | 「A の仕様変更でも B の仕様変更でも同じクラスを修正する」 |
| **影響** | 変更コンフリクトのリスク、変更影響の分離が困難 |
| **推奨パターン** | Extract Class（責務ごとに分離） |

### Shotgun Surgery（散弾銃手術）

| 項目 | 内容 |
|:---|:---|
| **定義** | 1 つの変更のために多数のクラスを修正する必要がある |
| **検出シグネチャ** | 1 機能の変更で 5 ファイル以上を修正 |
| **影響** | 変更漏れが発生しやすい、変更コストが高い |
| **推奨パターン** | Move Method + Move Field（関連コードを集約） |

## 3. アーキテクチャレベルの負債

### 循環依存（Circular Dependency）

| 項目 | 内容 |
|:---|:---|
| **定義** | モジュール A → B → C → A のような循環参照 |
| **検出方法** | 依存グラフを描き閉路を探す。madge（JS）/ pydeps（Python）等のツール |
| **影響** | 単体テスト困難、ビルド順序問題、変更の伝播 |
| **修正方向** | インターフェース導入、依存の反転（DIP）、イベントドリブン |

### レイヤー違反（Layer Violation）

| 項目 | 内容 |
|:---|:---|
| **定義** | UI が DB に直接アクセス等、アーキテクチャのレイヤー境界を越えた依存 |
| **検出方法** | import / require の依存方向を確認 |
| **影響** | 責務境界の崩壊、テスト困難 |
| **修正方向** | レポジトリパターン・サービスレイヤーの導入 |

### マジックナンバー / ハードコード

| 項目 | 内容 |
|:---|:---|
| **定義** | 意味のない数値リテラルや文字列のハードコード |
| **検出方法** | `grep -rn '[0-9]\{2,\}' src/` / 設定値の直接埋め込みを探す |
| **影響** | 変更のたびに全件 grep が必要、設定と実装が混在 |
| **修正方向** | 定数化（const MAX_RETRY = 3）、環境変数化、設定ファイル化 |

## 4. オブジェクト指向特有のスメル

### Refused Bequest（継承の拒絶）

| 項目 | 内容 |
|:---|:---|
| **定義** | サブクラスが親クラスのメソッドを使いたくない / オーバーライドして空にしている |
| **影響** | リスコフ置換原則（LSP）違反 |
| **推奨パターン** | Replace Inheritance with Delegation |

### Alternative Classes with Different Interfaces

| 項目 | 内容 |
|:---|:---|
| **定義** | 同じことをするが、インターフェース名が違うクラスが複数ある |
| **推奨パターン** | Rename Function + Pull Up Method |

### Data Class（データクラスの過多）

| 項目 | 内容 |
|:---|:---|
| **定義** | フィールドと getter/setter しか持たないクラス |
| **影響** | 振る舞いが散在し、Feature Envy を引き起こす |
| **推奨パターン** | Move Method（ロジックをデータクラスに移動）|

---

## スメル検出優先順位ガイド

| 優先度 | スメル | 理由 |
|:---|:---|:---|
| **最高** | God Class, Duplicate Code | 変更コストと影響範囲が最大 |
| **高** | Long Method, Feature Envy, Divergent Change | テスト困難・変更リスクに直結 |
| **中** | Long Parameter List, Data Clumps, Shotgun Surgery | 中程度の変更コスト |
| **低** | Dead Code, Speculative Generality | コードの汚染だが機能的影響は小さい |
