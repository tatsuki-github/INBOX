# リグレッションリスク管理チェックリスト

> improve-flow の Phase 5 実装後に実施する、改善変更によるリグレッション確認チェックリスト

---

## チェックリスト

### 型・インターフェース変更のリグレッション

| # | チェック項目 | 確認方法 |
|:---|:---|:---|
| R-1 | enum → リテラルユニオン変更後、全呼び出し箇所でコンパイルエラーがないか | `tsc --noEmit` |
| R-2 | タグ付きユニオン移行後、全 switch/if 文が新しい型に対応しているか | `never` チェックで確認 |
| R-3 | パブリック API の型変更が呼び出し元で正しく反映されているか | TypeScript エラーがゼロ |
| R-4 | 型エクスポートの変更が他モジュールに影響していないか | import している全ファイルを確認 |

### CSS / スタイル変更のリグレッション

| # | チェック項目 | 確認方法 |
|:---|:---|:---|
| R-5 | CSS 変数化した後、ハードコード値が残っていないか | grep で hex/rgb 値を検索 |
| R-6 | CSS 変数の定義漏れでスタイルが消えていないか | ブラウザで視覚確認 |
| R-7 | レスポンシブ変更が意図しない画面サイズに影響していないか | 各ブレイクポイントで確認 |
| R-8 | セレクタの変更が他コンポーネントのスタイルを上書きしていないか | DevTools で確認 |

### コンポーネント分割・移動のリグレッション

| # | チェック項目 | 確認方法 |
|:---|:---|:---|
| R-9 | コンポーネント分割後、props の受け渡しが正しいか | TypeScript エラー + 動作確認 |
| R-10 | ファイル移動後、全 import パスが更新されているか | `tsc --noEmit` |
| R-11 | 分割されたコンポーネントが独立して動作するか | 単体で動作確認 |

### パフォーマンス最適化のリグレッション

| # | チェック項目 | 確認方法 |
|:---|:---|:---|
| R-12 | React.memo 適用後、必要なタイミングで再レンダリングされているか | React DevTools Profiler |
| R-13 | useMemo/useCallback の依存配列が正しいか（deps 漏れ or 過剰） | eslint-plugin-react-hooks |
| R-14 | ページネーション導入後、既存の全件取得が必要な箇所が壊れていないか | 動作確認 |
| R-15 | N+1 クエリ解消のバッチクエリが全ケースで正しく動くか | ユニットテスト |

### バグ修正のリグレッション

| # | チェック項目 | 確認方法 |
|:---|:---|:---|
| R-16 | バグ修正が同じロジックを使う別箇所にも適用されているか | 類似コードを検索 |
| R-17 | null チェック追加後、null ケースの処理（フォールバック）が適切か | 動作確認 |
| R-18 | エラーハンドリング修正が UI に適切に反映されているか | エラーケースの動作確認 |

## リグレッションリスクレベルの判定

| 変更の種類 | リスクレベル | 必須チェック |
|:---|:---|:---|
| CSS 変数化（ハードコード置換のみ） | Low | R-5, R-6 |
| aria-label 追加 | Low | R-9（props 確認） |
| enum → リテラルユニオン | Medium | R-1, R-2, R-3, R-4 |
| コンポーネント分割 | Medium | R-9, R-10, R-11 |
| タグ付きユニオン移行 | High | R-1〜R-4 全て |
| パフォーマンス最適化（React.memo等） | Medium | R-12, R-13 |
| API・データフェッチ変更 | High | R-14, R-15 |

---

## リグレッション発見時の対応

| 発見タイミング | 対応 |
|:---|:---|
| Phase 5 実装中 | 即座に修正してから次の改善に進む |
| R5 フェーズレビュー | Phase 5 に差し戻して修正 |
| Phase 6 最終レビュー | 影響範囲に応じて Phase 4 or 5 に差し戻し |

> **原則**: リグレッションを発見したら「修正して進む」ではなく「修正して確認してから進む」。
> リグレッションの連鎖を防ぐため、1 つ発見したら同種の変更を全て確認する。
