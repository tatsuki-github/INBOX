# 全ナレッジ・チャンク別QA 作業台帳

依頼: 全ナレッジをチャンクに分け、各チャンクにつき既存にない想定QAを3件追加する。すべての品質確認とCIが成功したらmainへマージする。

- 正式な追加QAはまだ作成していない。チャンク台帳の生成をQA追加完了として数えない。

## 対象と作成規則

- まずKGのrefs、コーパスのsources.jsonとコーパス内の全文を対象として原資料を辿る。
- 正本と同じ本文のコピーは別のチャンクとして数えず、全コピーの対応を保存する。
- 既存QAと検索索引は自分自身の事実の根拠にしない。対象外のパスと理由も一覧に残す。
- チャンクは原則5000文字を上限に、段落・行、CSVレコード、JSON/YAMLの型付き単位で分割する。原資料の末尾や長いレコードを切り捨てない。
- 各チャンクに原資料のハッシュと文字範囲・CSV行・JSONポインタを付け、すべての本文/フィールドが残ることを独立した検証で確認する。
- 次に各チャンクを読み、既存QAに未追加の具体的な質問を3件選ぶ。薄い案内、同じ質問の水増し、推測を含む回答は採用しない。
- 各QAに該当チャンク、根拠の位置、事実対応の検証結果を保存する。回答本文には内部パスや生データダンプを入れない。
- 3件揃わないチャンクは未完了として明示し、勝手に省略して全件完了としない。空データ、索引、OCR不確実箇所は意味に基づいて原資料・チャンクの対応を見直す。
- 年・大会・男女・種目・学校/選手・区間・予想/実績を混同しない。過去の結果の質問には年を付ける。

## 完了条件

1. 全対象の内容がチャンク一覧に対応し、漏れ・欠損・未読・未解決チャンクがない。
2. 全チャンクに新規QAがちょうど3件紐付き、既存を含む正規化重複がない。
3. 全追加QAの事実、質問と回答の対応、検索一致と誤一致抑止を検証済み。
4. Prepared QA正本・backend JSON・コーパス・KGを同期し、監査とCIに問題がない。
5. 最新PR headでCIが成功した後mainへマージし、main上の追加件数と同期を確認する。
